  2. 浏览器解码为 ImageData，并限制最大边长。
  3. 按 input 层配置 resize、颜色模式、invert、normalize。
  4. 生成 prepared.tensor，作为 Python forward 的真实输入。

Conv2D 实现：局部感受野、参数校验与特征图输出

数学背景

卷积层用局部感受野扫描图像。每个 kernel 学习一种局部模式，例如边缘、纹理或颜色组合；输出通道数代表要提取多少组特征。

out_h = floor((H + 2P - D*(K-1) - 1) / S) + 1
项目实现
  • 前端允许修改 kernel、stride、padding、dilation、activation。
  • Python 校验参数组合是否合法，避免输出尺寸为负。
  • 右侧检查器展示公式、shape、特征图和统计值。
  • 卷积核对比功能可临时替换 kernel，观察同一输入下的输出差异。
层级解释Conv2D 页面把深度学习中的局部感受野、输出尺寸公式和特征图可视化统一到同一层检查器中。
用 Conv2D 连接深度学习概念和项目实现：参数、shape、特征图。

工程亮点 1：forward 请求竞争与防抖

问题

用户在调整网络参数时可能连续触发 forward。如果旧请求比新请求晚返回，就会覆盖新的结果；如果每个输入都立即请求，又会造成后端压力。

处理策略
forwardRequestSeq丢弃迟到的旧响应
forwardInFlight标记当前计算正在进行
forwardRerunRequested计算中又修改参数，结束后补跑一次
forwardDebounceTimer降低连续输入触发频率
交互稳定性连续改参数时，序号、in-flight 标记和补跑机制共同保证最终展示的是最新实验状态。
这是 Web 工程能力点：不是按钮发请求这么简单，而是处理真实交互里的异步竞争。

工程亮点 2：特征图渲染从 DOM 网格改为 Canvas 图片

早期问题

如果把 tensor 的每个像素渲染成 HTML 小格子，稍大的特征图就会产生大量 DOM 节点，布局和重绘成本很高。

现在方案
tensor values
  -> Canvas ImageData
  -> data URL
  -> <img> preview

多通道 tensor 默认只展示部分通道，完整通道放入弹窗，兼顾解释性和性能。

渲染优化把数值矩阵转为 Canvas/ImageData 后再展示，减少 DOM 节点数量，支撑多通道特征图的快速预览。
强调从 DOM 网格到 Canvas 图片的性能收益。
