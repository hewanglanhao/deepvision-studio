项目组成

平台由 Angular 前端、Spring Boot 后端和 Python 计算模块组成，用于完成可交互的深度学习实验。

开场简单介绍平台的技术组成和主要功能。

项目目标

现有学习方式的问题
  • 课件可以展示公式，但不容易看到每一层的 shape 和特征图变化。
  • 静态图缺少真实计算，无法直接比较修改参数前后的结果。
  • 深度学习术语较多，实验时经常还要另外查找概念。
平台提供的功能
编辑网络调整网络层、参数和样本输入
真实计算使用 Python 和 NumPy 执行前向传播
过程解释查看公式、shape 变化、特征图和助手回答
保存实验登录后保存并恢复实验记录
设计思路把网络编辑、真实计算、结果解释和实验记录放在同一个平台中。
重点说明平台不仅展示网络结构，还能运行计算并查看中间结果。

训练任务执行流程

01Angular 提交数据集、网络结构和超参数
02Spring 创建任务目录，写入 request.json
03Spring 启动 Python worker
04Python 持续输出训练事件
05Spring 推送进度并保存 checkpoint
为什么这样做
  • 每次训练单独启动一个 Python 子进程，任务结束后进程也会退出。
  • request.json 保存本次训练配置，控制文件处理暂停、继续和停止。
  • Python 每次输出一条 JSON 事件，Spring 读到后马上推送给前端。
job.writeRequest(); // 保存本次训练配置
writeControl(job, "running");

Process process = new ProcessBuilder(
    pythonExecutable, "-B", workerScript.toString(),
    "--request", job.requestFile().toString()
).redirectErrorStream(true).start();

// 两个后台任务分别读取事件并等待进程退出
executor.submit(() -> readWorkerOutput(job));
executor.submit(() -> waitForWorkerExit(job));
这里主要讲清楚 Spring 负责管理任务，Python 负责真正的模型训练。

网络层梯度分析

这些数值怎么看
  • grad_norm 是这一层的总体梯度大小，可以用来发现梯度过小或过大。
  • update_norm 是参数实际改变的大小，可以结合梯度判断学习率是否合适。
  • grad_mean / grad_max 分别看平均值和最大值，weight_norm 反映权重整体大小。
  • 上面两条曲线看随 step 的变化，下面的直方图看当前梯度分布。
曲线数据怎么保存
// 每次收到真实 backprop 事件，按层记录一个采样点
current.push({
  step: ++backpropHistoryStep,
  gradNorm: layer.gradNorm,
  updateNorm: layer.updateNorm,
  gradMean: layer.gradMean,
  gradMax: layer.gradMax,

  histogram: layer.gradHistogram ?? []

// 限制历史长度，避免长时间训练持续占用内存

Checkpoint 测试集评估

操作过程
  1. 用户从自己的历史训练记录中选择一个 Checkpoint。
  2. Spring 检查用户权限，并读取原来的数据集、网络结构和权重路径。
  3. Python 恢复模型，在原来的测试集上重新执行推理。
  4. 页面展示 loss、accuracy、样本数，以及部分样本的预测结果。

成员 C 模块：重构路径与工程难点

重构路径
  1. 先以嵌入方式验证 CNN Explainer 可在平台内运行，再逐步拆掉外部依赖。
  2. 从 Overview 开始重建 Angular 原生骨架，再逐层补回卷积、ReLU、池化和输出层的解释视图。
  3. 把用户状态、AI 助手、教学入口和平台统一样式接进 Mode C，完成模块化收口。
工程难点
  • 原项目是 Svelte 加静态资源驱动，无法直接复用为 Angular 组件，只能按功能拆解后重建。
  • 需要把总览拓扑和局部教学弹层解耦，同时保持真实推理数据和页面交互同步。
  • 卷积层演示不是静态插图，而是基于真实通道、真实 kernel 和真实输出位置组织逐步动画。
模块价值

成员 D 模块：QKV 教学与工程实现

QKV 教学结构
  • 不是只画出注意力矩阵，而是把 Query × Key、缩放、softmax、Value 汇入输出的链路逐步展开。
  • 让用户能把"某个格子为什么亮"和"它最终如何影响输出 token"联系起来理解。
  • 这种设计更适合课程答辩，因为它既能讲公式，也能讲交互和最终效果。
工程难点
  • 浏览器端 Transformer 运行时需要处理 tokenizer、ONNX Runtime、注意力张量提取和静态资源分发问题。
  • 教学可视化不等于直接把张量打印出来，还需要把高维 attention 和 QKV 过程压缩成人能看懂的交互界面。
  • 资源较大，因此又做了"源码保留、模型资源单独同步"的改造，降低仓库体积和协作成本。
模块价值
  • Mode D 的核心贡献是把 Transformer 的预测结果与内部依据放到同一页面里，用教学化方式串起来。
  • 不是只演示 attention matrix，而是把 Top-K、当前聚焦单元和 QKV 信息流一起解释。
  • 这一模块也复用了平台统一的 AI 与教学体系，说明平台不仅能承载 CNN，也能扩展到 Transformer 解释场景。
这一页讲完以后，老师基本就能理解 Mode D 不只是"又一个页面"，而是把 Transformer 教学、浏览器端推理和平台化接入结合在一起。

模式 E：反向传播引擎与子步骤动画

纯前端 MLP 引擎（零依赖）
  • 手写矩阵运算：dot、transpose、hadamard、softmax — 无任何数值库依赖
  • 完整实现 Dense 层、ReLU/Sigmoid/Tanh 激活函数的正向和反向传播
  • CrossEntropy / MSE 损失 + Softmax 合并梯度优化
  • SGD / Momentum / Adam 三种优化器，每种都有独立的动量/二阶矩状态
逐层子步骤动画状态机
idle → forward-0-1 → forward-1-2 → ... → loss
     → backward-2-1 → backward-1-0
     → update-1 → update-2 → done

  • 蓝色脉冲 = 前向数据流、橙色脉冲 = 反向梯度流、绿色脉冲 = 参数更新
  • 流动光点沿权重边线动画移动，直观展示数据传递方向
教学价值不是瞬间跳过训练过程，而是把每一步拆成逐层可视化的教学演示，让"反向传播"四个字变成能看到的动画。

模式 E：损失曲线对比

优化器 / 激活函数对比
  • 跑完指定步数自动保存平滑平均损失曲线，标签标注优化器+激活函数组合
  • 可对比不同优化器（SGD/Momentum/Adam）和不同激活函数（ReLU/Sigmoid/Tanh）的收敛效果
  • 8 色调色板自动分配、颜色不重复、支持单条删除
  • 灰色虚线=单步原始损失、彩色实线=不同配置的平滑平均损失
  • 曲线自动标注最终准确率，点击弹出居中放大视图
控制面板
  • 三个预设网络可切换（XOR/同心圆/高斯团）
  • 激活函数：ReLU / Sigmoid / Tanh 一键切换
  • 优化器：SGD / Momentum / Adam，均挂载教学术语高亮
  • 学习率滑块 + 训练步数 + 播放速度 全部可调
  • 12 个教学术语接入共享教学文档，点击"?"即可跳转
对比实验同一数据集 → 切优化器跑一轮 → 自动保存曲线 → 切激活函数再跑 → 多条曲线叠加对比，直观感受不同配置的收敛差异。
